# Decisions

Resolved defaults for implementers. Update this file when a decision changes;
do not leave conflicting guidance across docs.

| ID | Decision | Rationale |
| --- | --- | --- |
| D1 | Tool Python field name is `pythonExecutable` (not `pythonCommand`) everywhere | One name across settings, IPC, and docs |
| D2 | Prefer JoyCaption `invocationMode: 'direct'` (venv `python.exe` + script args). Keep `cmd` as fallback only | Avoids shell string interpolation; matches AI Toolkit style |
| D3 | Training output folder = `{dataset.folderPath}/output`; the current form has no per-job output override and job save rematerialises this path | Keeps training artifacts out of the image root and lets destructive guards require a dedicated output folder |
| D4 | Job **source of truth** = JSON `config` on the job record; `config.yaml` is always regenerated on save and before run | Prevents JSON/YAML drift |
| D5 | **Remove from library** is metadata-only and is available only for a folderless legacy/fallback category. **Delete dataset…** removes the dataset folder after confirmation, while refusing category roots, running/paused training, and Validation Steps on that dataset. The current idle guard does not check the other Comfy tools | Distinguishes reversible catalog removal from explicit on-disk deletion |
| D6 | Dataset scan is **non-recursive** (files directly in `folderPath` only) | Matches typical LoRA folder layout; avoids nested surprises |
| D7 | Caption files are UTF-8 text; writes use UTF-8 without BOM | Cross-tool compatibility |
| D8 | One caption file per basename: if both `a.jpg` and `a.png` exist, they share `a.txt` (warn in UI) | Matches AI Toolkit pairing by stem |
| D9 | Pause = terminate process tree + status `paused`; Resume = spawn again with same YAML (checkpoint behavior is toolkit’s) | Toolkit may lack cooperative pause |
| D10 | Training is always single-flight. With `allowConcurrentCaptioning: false`, Queue Start refuses when JoyCaption is already active; `true` permits that overlap. JoyCaption has no reciprocal training-busy guard | Avoid accidental overlap on the normal Start path while preserving the stored opt-in |
| D11 | First-launch default training config = clone of `reference/config-sample.yaml` with placeholders left for job materialisation; `model.name_or_path` stays as in sample until user edits | Ship a working form without empty required fields |
| D12 | Serve dataset thumbnails via a **custom privileged protocol** registered in main (e.g. `loratraining-media://`), not raw `file://` from the renderer | Keeps sandbox; path-gated to registered dataset folders |
| D13 | On Windows stop/pause, kill the **process tree** (`taskkill /PID … /T /F` or equivalent) | Python often spawns children; killing only the parent leaves GPU work running |
| D14 | Queue reorder shipped in v0.1.0 (drag-and-drop; see `reorderQueue` in `src/main/queue/engine.ts`), superseding the original "FIFO only for v1" scope | User feedback during v1 development made priority reordering necessary before first release |
| D15 | Validation LoRA staging subfolder is **Settings-only** (`comfy.validationLoraSubfolder`) as the *default*; no per-dataset override field. Output checkbox **ON** copies when the basename is missing **anywhere** under `models/loras`, into the **same folder as sibling checkpoints** for that dataset (prefs + disk), else the Settings default. **OFF** deletes the staged copy if found in the subtree. Path column is healed on Output list | One shared folder per dataset; tick keeps a real Comfy copy |
| D16 | Upscale field values are **last-used** in library `lastUpscaleConfig` (not per-image sidecars); empty prompt ← image caption | Faster iteration across images; caption is the natural per-image default |
| D17 | Diversify has **Context** + **Expression** tabs (separate workflows); outputs are sort-adjacent `{root}_dNN` siblings; Run all = **roots only**; Context: prompt/seed/count + LT Prompt/Seed; Expression: **count only** in UI, injects LT Input Image + **Seed (always random each run)** + Output Folder + Filename (no Prompt); no model field; Context prompt never caption-filled; **Expression** copies the parent `.txt` caption onto new siblings; **Context** does not (scene/clothing change → re-caption) | Expression needs app-side random seeds; Context needs deliberate prompts; Context captions would be wrong |
| D18 | Each Comfy Edit-Workflow tool uses an **isolated** webview partition (`persist:comfyui-<tool>`), Save is gated until that tool’s graph loads, Save confirms the tool name, and every overwrite keeps `{libraryRoot}/!WorkflowBackups/{stem}/last.bak` (+ `.bak.1`) plus timestamped history there (save **refuses** if `last.bak` cannot be written) | Shared session previously let Validation Save overwrite with Upscale’s graph — **critical data loss** |
| D19 | Job **LoRA name** (`config.name`) is editable; default on create / dataset switch is existing `{folder}/output` checkpoint stem if any, else `Category_Dataset` (sanitize). Do not force dataset-only names on save; duplicates keep the cloned stem | Resume-compatible with old outputs (`OldName_*.safetensors`); new jobs prefer clearer Category_Dataset stems |
| D20 | Job **`config` (training settings)** is written only by user save (`updateJob`) and intentional authorship (create / duplicate / folder remap). Queue/runtime uses `patchJobRuntime` and never replaces `config`. Planned step counts always come from `train.steps`, never from tqdm `progress.totalSteps` (often total−2) | User settings must not be silently rewritten by fail/complete/progress |
| D21 | Validation Steps / Weight / Stress / Upscale **prompt** fields use a shared CodeMirror `PromptField` (Dynamic Prompts highlighting + `__wildcard__` autocomplete). Keys come from Settings → External tools → ComfyUI → **Wildcards** (`comfy.wildcardLibraryFolder`). Diversify and training sample prompts stay plain textareas | Match WildcardsManager editing UX where Comfy prompts matter; avoid caption/training-noise surfaces |
| D22 | While training (and across the inter-job cooldown): `prevent-app-suspension` + `prevent-display-sleep`; High priority + EcoQoS-off on the toolkit **process tree** and Electron; refresh every **5s** and again on window **blur/focus**; `backgroundThrottling: false` + `CalculateNativeWinOcclusion` disabled. Training stays `windowsHide` (not detached — that pops a console) | Win11 re-applies Efficiency Mode when unfocused — dataloaders starve GPU (s/it + fan drop until focus returns) |
| D23 | In-app updates: empty `updateCheckFolder` checks GitHub Releases for `aipower66669/LoraTraining` and downloads `LoraTraining Setup X.Y.Z.exe`. A non-empty folder overrides that and scans local Setup exes only. **What's new** renders that version’s release notes (GitHub release body, or `RELEASE_NOTES.md` in the folder / its parent). Install is `shell.openPath` + `app.quit()` — not `electron-updater` | Local folder stays the developer override; everyone else gets the public release. Installer finish-page “Run” starts the new build after replace |
| D24 | App window opens before library discovery; renderer `refreshAll` loads categories then datasets async (`libraryLoading` until sticky sidecars arrive). `listDatasets` emits sticky summaries first, then enriches covers/badges prioritizing the active explorer tab (Done last). Main does not `await listDatasets()` before `createWindow` | Cold-disk first launch after reboot was blocked on full category sync + per-dataset output walks; tab-priority makes Queue/Validated feel instant |
| D25 | Electron UI disables hardware acceleration (`app.disableHardwareAcceleration` + Chromium `--disable-gpu` / WebGL / WebGPU / video decode). Compositing uses SwiftShader CPU. Does not apply to spawned Python/Comfy | Leave NVIDIA VRAM for training; this shell is not a GPU client |
| D26 | Training **model** (checkpoint path, arch, quantize, low VRAM, layer offloading) is library-wide in `settings.defaultTrainingConfig.model`. YAML written at job start/export overlays this onto the job; the Jobs form no longer edits it | One GPU/VRAM policy for 200+ jobs; changing Settings once applies to the whole queue |
| D27 | **Image edit / Upscale NTFS versions are opt-in and default off.** Off: overwrite the image body like a conventional editor and clear an existing stack on the next save. On + NTFS: `$DATA` = pristine; tips in `VER_1…VER_4` + `VER_COUNT`; Undo last drops the tip; **Revert to original** deletes all `VER_*`; Upscale sources `$DATA` and writes a tip. Non-NTFS always overwrites. Diversify resolves an existing tip. JoyCaption/training permanently Commit existing tips before run. Legacy `{file}.original` → ADS migration runs only while enabled | Normal users get expected overwrite behavior; NTFS folders can opt into reversible history |
| D28 | On Windows, training spawns `train_bootstrap.py` which patches `safetensors` to prefer `pread`. Stream via seek/read only when the API is missing. **On OSError 1455 / commit exhaustion: abort immediately** — never fall through to a heavier loader (that made the OS worse). Logs commit snapshot at start. Opt out: `LORA_TRAINING_ALLOW_SAFETENSORS_MMAP=1` | 1455 is system-wide commit starvation; retrying/streaming after failure can brick other apps until reboot / killing leftover `python.exe` |
| D29 | Edit Image loads tip bytes once into memory. Before **Crop** (and before **Remove**), bake Filerobot’s current design into a new working data-URL source and remount so ops chain without Save → re-open — Filerobot does not keep rotation (or other in-session design) in the crop UI (upstream #267). Disk write still only on Save. Handle behavior is free-form crop, hold the live box until pointer-up, Resize lock uses the current/cropped aspect, and `noScale` so the clamp stays in shown-image pixels. **Crop preview is 1× and the outside-crop dim is opacity, not Konva Blur** — D25 rasters this shell on the CPU, and that blur is a full-window `getImageData` (a few fps; the position update and the size update paint as two frames). Save still uses up to 2× pixel ratio | Rotate/filter/annotate → crop without Save; handle drag stays interactive on the software canvas; locked resize keeps crop aspect |
| D30 | Tool-dependent UI is capability-gated by required configured paths: JoyCaption Work dir reveals automatic caption actions + Description; AI Toolkit Work dir reveals Jobs, Queue, job actions/drawer, library Queue status, pending rows, and Default training config; Comfy LoRAs reveals its six dataset tools, image actions, checkpoint controls, and Output validation details. Settings and manual dataset/caption work stay visible. Caption Stop and a live training process’s Queue/Stop survive a path being cleared | Keep first-time and dataset-only use uncluttered without deleting durable jobs/outputs or stranding a running process |
